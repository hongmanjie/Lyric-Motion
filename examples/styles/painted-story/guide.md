# 纸绘叙事：先讲清一个故事

先阅读 [story-planning.md](story-planning.md)，查看 [原创画面参考](visual-reference.svg)，再结合 prompt.md 和 profile.json 创作。不要先写几组背景，再把歌词贴上去。

由 Agent 先完成当前歌曲的歌词拆解、故事梗概、角色弧线、贯穿道具与分镜事件，写在工程的 STORY.md 或等价文件。用户不需要填写这些内容，也不需要为已授权的常规创意逐步确认。

每镜要贴近当前歌词，也要让完整故事向前走：主角有想做的事，环境或关系构成阻碍，动作带来结果，结果影响下一个选择。重复歌词必须带来新的事件、理解或关系，不能只是换色、换姿态或重复同一场景。

场景回归可以很有力量，但要有意义变化。用眼神、手、接触、物件用途和反应体现这种变化；片尾回收开头的铺垫。全景说明处境，近景看选择，特写承载关键动作。不要用字幕解释本该看出来的事情。

story-kit.mjs 提供可选的确定性表演积木：actionPhase 分开预备、动作与反应；lerpFace 连续过渡表情；handPositions 返回随旋转和朝向变化的接触坐标；createPuppetPainter 是可改写的 2D 角色骨架。新主角可以重画，只借用时序与接触辅助，不限定狐狸、猫、兔或任何固定故事。

纸、墨线和少量颗粒形成材料统一。角色与道具保持连续；变化优先来自情节、景别和表演。用当前歌曲的真实时长和歌词时间，实测能量只作辅助，不伪造拍点或逐字对齐。

最后检查完整连续播放，尤其比较重复段落。记录每次回归新增了什么，修正物件漂浮、接触不实、角色重复和只有背景变化的空镜；检查字幕与动作是否冲突。技术通过不等于故事成立。
