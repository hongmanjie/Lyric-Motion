# 从歌词到完整故事

这是 Agent 内部的创作流程，用户只要提供歌曲、歌词和可选方向。不要把以下项目变成用户需要填写的表，也不要把任何示例故事固定成模板。

## 1. 先读懂这一首歌

在编码前同时阅读歌词时间与实际音乐结构，再写出一份简洁分析：每段表面在说什么，真正的情绪是什么，叙述者想得到什么，哪一句改变了它的理解。同一歌词重唱时，角色已经经历了什么，为什么此时唱这句？

区别具体事实和创作推演。歌词没有说死亡、出轨或重逢，就不要擅自将这些设为唯一解释。喜悦、愤怒、幽默、成长或怀念各有自己的戏剧结构，不把每首歌都改成失恋后被治愈。

## 2. 用一句话讲出属于它的故事

写下“主角想做一件具体的事，遇到阻碍，采取行动，付出代价或看见新信息，最后作出与开头不同的选择”。要有动词和因果，不能只写“从悲伤走向希望”。

再写几个有因果关系的段落，覆盖歌曲的建立、发展、转折和结尾。某段可以悬而未决，结局也可以悲伤；完整意味着铺垫有去向、角色的行为有后果，不意味着必须团圆。

## 3. 为新歌选择贯穿物

少量原创道具或空间关系会让观众记住故事。给每件贯穿物明确的初始意义、经过的动作和最后用途。例如：同一物件可以从阻碍变成工具，曾经收到的动作可以在后来送给别人。这里的机制可迁移，示例中的车票、花、伞、纸船不应被所有新歌照搬。

记录人物、衣着、道具的状态和去向：拿在哪只手、是否破损、上一镜落在哪里、下一镜为何出现。物件不能无缘无故复原、换手或瞬移。片尾若回应开头，至少有一个可见选择真正改变。

## 4. 每个镜头同时服务歌词和故事

由 Agent 写进当前工程 STORY.md 或等价文件，形式可自由。每镜至少想清楚：

- **这句的语义**：不是只找一个名词当背景，而是看人物正在表达的处境和关系。
- **开始状态 → 事件 → 反应 → 结束状态**：观众在这镜看懂了什么新东西？主角试、等、失败、接受、决定或帮助了什么？
- **观看顺序**：先看哪里，再看什么，哪段时间给动作预备，哪段给理解和情绪停留。
- **构图与衔接**：为什么用特写或远景，上一镜的视线、道具、方向或形状如何交给下一镜。

一个镜头不必等于一行歌词。一句也可用两个因果镜头；连续几句可以完成一个充分表演的事件。不要规定所有歌曲的镜头数量或固定秒数。

## 5. 编码前做一次不重复检查

逐镜写出“地点＋事件＋人物选择”。若连续几段只是“主角站在某地＋轻晃＋背景变化”，重写事件。若删去或交换中间镜头，故事依然完全一样，说明因果太弱。

重复歌词不能直接复制第一次的镜头。同一地点回归，应带来新的信息、人物关系或行为结果；只把夜景改成白天、只换颜色和姿态，不足以构成推进。两遍副歌可以形成“尝试和后果”“误解和理解”“接受照顾和给出照顾”等关系，也可以根据新歌另想一种结构。

不要求每句换新地点。应保留必要的呼应，改变景别、可见事件和意义；随机堆新场景同样会把短片拆散。追求的是一个连续的故事，而不是地点数量。

## 6. 演出，而不是展示插图

先画出能读懂的关键姿态。视线先察觉，身体再转向，手接触物件，物件最后跟随，表情留出反应。重要动作有预备、发生和结果；强音可以推动动作落点，意义仍要给观众时间理解。

story-kit.mjs 提供独立动作阶段、表情插值、稳定手部坐标和一个可编辑纸绘角色积木。按当前主角改写外形或只使用时序与接触辅助，不强制采用狐狸、猫或兔。角色和物件的接触要检查实际帧，不能认为返回了坐标就自然正确。

## 7. 实际观看再交付

检查全尺寸关键帧、开始/中间/结束姿态、接触点、道具连续性和字幕。连续播放完整成片，并专门复看重复段落：每次回归是否真的多讲了一件事？主角为什么改变，能否从动作理解？

发现只有“移动了元素”而看不懂事件，就调整动作顺序、景别或停留，不只加纹理和粒子。记录真正观察的范围和听音限制。技术确定性不能保证故事成立；不承诺同一提示词在任何模型上都得到同样质量。

## 非演唱内容与音乐段落

署名、来源网站提示和“纯音乐，请欣赏”不是唱词；原文仍保留在输入和注释中，不能长时间当字幕。文件明确声明纯音乐时，以音乐和自创故事推进，不编造歌词，也不把文件声明写成已经主观听过的结论。

同一段旋律或歌词的回归，应比较人物已发生的变化：第一次犹豫、第二次主动，或第一次只回应一个人、后来回应更多人。可以有完全不同的情绪结构；这是检查意义变化的方法，不是新的固定剧本。
