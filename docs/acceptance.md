# v0.1.0 验收范围

普通用户只需对话。首页保留五项能力，安装由 Agent 完成；下面是维护者实际验证与仍需用户判断的边界。

| 工作流 | 工具保证与验证 | 需要人工或模型完成 |
| --- | --- | --- |
| 生成歌词 | 本地识别能输出 LRC/SRT/原始转写与待校对状态；有真实人声片段识别和导入记录 | 歌词准确度、唱词与时间校对；不冒充外部歌词强制对齐 |
| 选择风格 | 两个完整风格包可导出、搬移并导入；新歌实际制作使用了安装副本与风格 1 | 新歌的故事、美术、表演与实际观看；不是固定画面模板 |
| 自由创作 | auto 不强加内置包；原始工具演示可确定性预览、导出 | 用户歌曲的原创构思由 Agent 实际编写，工具不自动生成艺术作品 |
| 提炼风格 | 参考工具准备证据帧与连续预览；档案/提示词可校验与导出 | Agent 实际观看，区分观察、推测与未听音，不声称恢复私人原始提示词 |
| 参考复刻 | 分析资料能随新歌曲导入独立工程，再走同一预览/导出流程 | 参考理解与复刻质量由实际新作验收，网页标题不能代替观看 |

## 当前发布检查

逻辑测试覆盖歌词解析、真实媒体导入、两种客户端的安装文件布局、风格包搬移、参考资料、音频特征、HTTP/定位/导出契约，以及慢帧尾帧与重新播放、交付来源和旧版本保护。共享运行时修改后，原始演示必须重新检查并渲染。GitHub Actions 的实际状态见首页徽章。

维护者本地 Windows 上执行过两种已安装工具副本的命令与渲染，GitHub Actions 在 Linux 执行测试和原始演示渲染。Codex/Claude Code 各自全新会话的自动发现、macOS 及所有模型的艺术效果，没有被这些文件或命令测试证明。

## 验收一支自己的 MV

先看画面能否讲清这一首歌：重复段落是否推进不同事件、角色与道具有无断裂、字幕是否清楚。再检查完整播放、导出文件及可编辑工程是否确实可用。qa/review.md/json 应记录实际观察的帧、连续播放范围、已修问题与是否主观听到声音。没有听音能力时保留限制，不用波形或播放进度冒充听过。

完整用户歌曲和私人工程不进入开源包；公开示例仍只有维护者明确选择的两段。每份本地交付有文件哈希，之前的好版本保留。
